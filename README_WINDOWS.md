# JARVIS PWA — Voice Beta (Windows + iPhone)

Это **первая интеграционная версия**, не релиз для клиентов. Сохранён согласованный дизайн JARVIS PWA 2.0: единственная сфера, без кнопок и без вывода текста разговора. Искусственный интеллект остаётся в **JARVIS — Dialog Stable** через n8n и GPT; ElevenLabs используется **только как озвучка**.

## Что уже сделано в коде

- Доступ к приложению по коду (сеансовая HTTP-only cookie, SameSite=Strict).
- Запись аудио в браузере, определение паузы, распознавание через OpenAI Audio Transcriptions.
- Отправка распознанного текста в действующий n8n `/webhook/jarvis-dialog`.
- Использование ответа `speak` от n8n без его отображения на экране.
- Потоковая озвучка через ElevenLabs TTS, без ElevenLabs Agents.
- Нажатие на сферу для начала, досрочной отправки реплики, отмены ожидания и перебивания ответа; удержание сферы ~850 мс для завершения.
- Экспериментальное перебивание голосом при воспроизведении, требующее проверки на реальном iPhone.
- Неизменённая графика 2.0; поддержка PWA для добавления на главный экран.

**Не сделано/не проверено:** нет активного сервера в интернете; нет подключения к API с вашими реальными секретами; нет тестирования живого голоса на вашем iPhone; фоновой работы нет; много-клиентская авторизация и Claude ещё не подключены. При одновременном воспроизведении и записи браузер может создавать эхо, поэтому голосовое перебивание экспериментальное. В зависимости от ограничений автозапуска аудио iOS может потребоваться дополнительное касание сферы для включения звука.

## 1. Запуск на Windows

1. Установите **Node.js 20 или новее** (Node.js 22 предпочтительнее).
2. Распакуйте архив, откройте папку `JARVIS_PWA_Voice_Beta`.
3. Скопируйте `.env.example` в `.env`.
4. Заполните в `.env` **только на своём компьютере/сервере** значения ключей. Не присылайте этот файл в чат.
5. В Проводнике в адресной строке этой папки введите `cmd`, затем в терминале: `npm start`.
6. В браузере Windows перейдите на `http://localhost:3000`; введите ваш `JARVIS_ACCESS_CODE`. Микрофон на `localhost` может работать без HTTPS, но удалённый доступ с iPhone — нет.

### Откуда брать конфигурацию

- `N8N_DIALOG_URL` — **production URL** вебхука `Dialog — Secure Webhook` в `JARVIS — Dialog Stable`.
- `N8N_AUTH_HEADER_NAME` + `N8N_AUTH_HEADER_VALUE` — те же имя и значение, что заданы в **Header Auth** credential `JARVIS — Siri Security` внутри n8n (не сама подпись credential).
- `OPENAI_API_KEY` — ключ API OpenAI, только для распознавания речи. `OPENAI_STT_MODEL=gpt-4o-mini-transcribe` (поддерживаемая модель распознавания, выбранная для демо). Текущий GPT для понимания запросов **не меняется**, он уже внутри Dialog/REST/MCP.
- `ELEVENLABS_API_KEY` — ключ вашего ElevenLabs (в нём сейчас сохранены n8n credentials).
- `ELEVENLABS_VOICE_ID` — ID голоса из `OpenAI — Generate MP3`, узел `ElevenLabs — Generate MP3`, строка URL.
- `ELEVENLABS_MODEL_ID` — исходная модель `eleven_v4` (как в присланном workflow). Можно потом протестировать другие модели на скорость/качество.
- `JARVIS_ACCESS_CODE` — собственный **длинный пароль от 12 символов**, его никогда не использовать как токен Битрикс24.

### Только для демонстрации интерфейса

Можно поставить `DEMO_MODE=true`, использовать любой длинный `JARVIS_ACCESS_CODE` и не заполнять внешние API-ключи. В таком режиме настоящая интеграция не работает: экран показывает анимацию, а нажатия не меняют данные CRM.

## 2. Как запустить на iPhone — бесплатно

`http://localhost:3000` на Windows нельзя открыть на iPhone как PWA с доступом к микрофону. Нужно разместить **этот Node.js-сервер на HTTPS-домене** (например, через сервис с поддержкой Node.js, такой как Render или Railway).

1. Загрузите проект в **закрытый** репозиторий GitHub (без файла `.env`).
2. Настройте Node.js-развёртывание с командой `npm start`; перенесите переменные из `.env` в секретные Environment Variables платформы.
3. Проверьте, что HTTPS активен, откройте сайт в Safari на iPhone.
4. Safari → «Поделиться» → «На экран “Домой”».
5. Запустите JARVIS с главного экрана, введите код, нажмите сферу и разрешите микрофон.

Приложение не предназначено для публикации в открытом доступе без дополнительного аудита безопасности, защиты данных и авторизации пользователей. Без подключённых секретов голос работать не будет. Платный аккаунт Apple Developer **не нужен**. Стоимость hosting/API может быть ненулевой.

## 3. Как проверять

1. Попросите: «Какие у меня задачи на сегодня?» — проверьте актуальность данных в Битрикс24.
2. Перебейте ответ нажатием сферы; затем попробуйте голосом (может зависеть от iOS).
3. Спросите: «А какие просроченные?» — проверьте контекст диалога.
4. Попросите создать тестовую задачу — убедитесь, что Джарвис **требует подтверждения** и без него ничего не создаёт.
5. Закройте сессию долгим касанием, снова запустите.

## 4. Важные ограничения текущих workflow

- `Dialog Stable` строго требует `device_id='my-iphone'`. Поэтому сервер демо передаёт **только эту константу**, а не произвольный ID браузера.
- `REST Stable` содержит URL конкретного портала и `ownerUserId=1` внутри ноды `CONFIG + Validate input`. Для других компаний это надо выносить в защищённую конфигурацию **и отдельно проверять права доступа**.
- `MCP Astra` использует фиксированное подключение к одному порталу. Массовое подключение клиентов требует отдельной авторизации каждого портала (например, OAuth).
- `session_id` создаётся на каждую голосовую сессию, чтобы не смешивать контекст нескольких разговоров на одном демопортале.

**Для клиента сейчас не копируйте этот сервер без адаптации:** PIN общий для единственной демо-учётки, это не полноценная мультиарендная изоляция. Архитектуру по переносу в многоклиентский режим см. `docs/UNIVERSAL_ARCHITECTURE.md`.
